# Conformal Calibration of Emergency Department Deterioration Risk Under Temporal Shift

Source code for a study of static, adaptive, and class-conditional conformal calibration of deterioration-risk models on
MIMIC-IV-ED, evaluated on a chronological split. The study is Module 2 of the SihhaDZ research project.

**Status.** The manuscript is in preparation. A citation entry will be added here once a preprint or article exists.

## What the study asks

A risk score for emergency-department patients is more useful with an uncertainty statement that holds at a known rate.
Conformal prediction provides such statements under exchangeability, which a change in the patient population can
violate. The study asks two questions:

1. Does a static split-conformal calibration remain valid on a later period, or does a hospital need an adaptive method
   such as Error-quantified Conformal Inference (ECI, ICLR 2025)?
2. Does coverage over all patients also hold for the small group of patients who deteriorate?

Each stay is scored retrospectively from its full emergency-department record, so the task is classification at the end
of the stay, not early warning at triage. The outcome is in-hospital death or transfer to an intensive care unit within
12 hours of departure. The cohort is a retrospective, single-center proxy.

## Main findings

This README contains no result numbers. Every number is regenerated by the scripts below, stored in `data/`, and traced
in `M2_Findings_Dossier.md`. In qualitative terms:

- Static split-conformal calibration kept its nominal marginal coverage on the later period.
- ECI and periodic recalibration did not improve on it; ECI produced wider intervals, and with labels delayed by
  thousands of arrivals it over-covered with near-vacuous intervals.
- A controlled drift experiment shows that the evaluation can detect an adaptive benefit when one exists.
- Marginal coverage did not translate into comparable coverage for the patients who deteriorate. Class-conditional
  (Mondrian) calibration restored it.

An earlier version of this README described ECI as the primary contribution and claimed tighter intervals. The
pre-specified comparisons did not support that claim, and the dossier records the retraction.

## Data

**No patient data are included.** MIMIC-IV-ED and MIMIC-IV are controlled-access resources: you need a credentialed
[PhysioNet](https://physionet.org/content/mimic-iv-ed/2.2/) account, the required training, and a signed data use
agreement. Patient-level files, per-stay predictions, split identifiers, notebooks, and trained model weights are
excluded on purpose.

`mimic4ed-benchmark-main/data/` contains only aggregate result files (summary tables, bootstrap outputs, tuned
configurations, fitted scaling constants). They let you regenerate every table and number macro in the paper without
MIMIC access; they do not let you retrain models.

## Setup

```bash
cd mimic4ed-benchmark-main
python -m venv .venv && . .venv/Scripts/activate      # use .venv/bin/activate on POSIX
pip install -r requirements.txt
```

`requirements.txt` pins a CUDA-linked PyTorch build and falls back to CPU when no matching driver is present. A GPU is
not required, but the GRU-D runs are considerably faster with one.

## Reproducing

From `mimic4ed-benchmark-main/`, with credentialed MIMIC-IV-ED data extracted locally:

```bash
python experiments/run_reproducible_m2.py --config configs/paper_track_m2.yaml
```

This runs the chronological pipeline (the `v2` track) with five fixed seeds `{42, 123, 7, 456, 789}`. Add
`--from-scratch` to start from the raw MIMIC-IV-ED extraction, and `--stage <name>` to run one stage. The overnight run
order is also written out in `Benchmark_scripts/run_full_v2_grid.sh`.

Without MIMIC access, regenerate and verify the paper assets from the aggregate files in `data/`:

```bash
python src/generate_latex_tables.py     # tables -> paper_assets/tables/
python src/generate_paper_macros.py     # number macros -> paper_assets/tables/m2_numbers.tex
python src/verify_paper_assets.py       # replays every recorded value and cross-checks it against the stored files
python src/cohort_demographics.py       # cohort description (needs the local split files)
```

`verify_paper_assets.py` also needs the local patient-level files for the checks that hash them; the evidence manifest in
`results/` lists the hashes.
